🖥️ forza-gui + ⌨️ forza-cli top

GUI (Slint): Tokio runtime on a dedicated thread; callbacks only enqueue over mpsc, results come back via invoke_from_event_loop. State in ui_state.rs, handlers in callbacks/*, IO in worker.rs.

CLI (bin forza): Clap; declares a dependency on forza-gui (launch/reuse) — the binary is never lightweight.

Depends on

GUI: config, db, domain, app, output, pipeline · CLI: all of those + gui

⚠️ Reading notes (graph interpretation)

SignalMeaning
forza-app with 6 depsNatural hub given the orchestrator role. Changes here affect GUI+CLI together.
forza-cli → forza-guiThe only sideways/upward edge. The CLI is not independent of the GUI — intentional (launch), but it rules out a lightweight CLI binary.
Dual base (domain + config)Correct split: rules (domain) never touch settings (config). No workspace dependency cycles.
BestLapRow in forza-app, trait LapRow in domain::orderingDomain must not reference the concrete struct (would be a cycle). The trait is the contract, the struct is the implementation.
